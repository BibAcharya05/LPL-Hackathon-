# Transition Copilot workstation

The existing React, Vite and TypeScript application uses the spatial patterns of [Mantis Free](https://mantisdashboard.com/free/): a compact shell, white sidebar, restrained metric cards, and a table as the primary workspace. The account review pairs source evidence with a document checklist. No Mantis source or hosted bundles are included.

## Theme

Tokens are centralized in `src/index.css`. Inter is retained with a system sans-serif fallback. The canvas is #F7F8FA; surfaces are white; borders are #E4E7EC. The 64px header is #102C4C; controls use #173A63 and selected navigation uses #EAF0F6. Text is #182230 with #667085 supporting text. Corners are 6–8px; spacing follows an 8px rhythm with 4px adjustments for compact controls.

Readiness has both an icon and a text label: Ready #067647/#ECFDF3; Missing Info #A15C07/#FFFAEB; Flagged #B42318/#FEF3F2; Submitted #175CD3/#EFF8FF. Counts and document completeness come from account results. No simulated trends or financial metrics are generated by the frontend.

## Components and interaction

Locally owned Button and Dialog primitives follow shadcn/ui composition patterns using CVA, Radix Slot and Radix Dialog. Radix manages modal semantics, focus trapping and Escape dismissal. Shared status chips and document labels keep the dashboard and review consistent. All icons use Lucide outlines.

The 240px desktop sidebar collapses to 72px. Below 1024px it becomes a modal drawer. Below 768px cards rearrange, review columns stack and header actions use accessible icon buttons. The table scrolls within its own region; the page has no fixed desktop minimum width. Focus outlines and reduced-motion styles apply throughout.

Search, status filtering, sorting, refresh, account review and upload remain connected to existing data. Readiness never authorizes a transfer. Synthetic-document confirmation and the existing packet/upload API contract are retained. Poll failures can resume status checking without creating another upload.

## Development

`npm run dev` serves Vite; local `/api` requests proxy to port 8000. The existing `/ports/8000/api` proxy is retained. `API_PROXY_TARGET` can override the development proxy for local fixture testing. Production requests remain deployment-relative and do not use this development proxy. Validate with `npx tsc --noEmit` and `npm run build`.

## Validation

Browser checks used a localhost synthetic API fixture, including the existing saved T002 result. Verified status-card and toolbar filtering, search, no-match recovery, client sorting, account review, document completeness, sidebar collapse, mobile navigation, dialog focus trapping and restoration, upload confirmation, status-check recovery, completion refresh, empty accounts and recoverable service errors. Responsive layouts were inspected at 1440×1000, 768×1024 and 375×812. Table overflow remains contained on mobile. Relative requests were checked at both `/` and `/ports/8000/`.

These checks do not validate live S3, Textract, Bedrock or DynamoDB processing; backend integrations were not changed. No live deployment was performed.
